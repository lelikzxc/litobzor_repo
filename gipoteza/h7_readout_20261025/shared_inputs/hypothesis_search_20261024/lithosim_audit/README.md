# LithoSim: аудит доступности и разметки на маленьком TRAIN-шарде

24 октября 2026 года. Это предварительный аудит данных для выбора новой гипотезы, без обучения и без доступа к test. Проверяется возможность классификации изменений связности печатаемого рисунка при изменении параметров процесса.

## Первоисточники и доступность

- [Статья NeurIPS 2025](https://papers.nips.cc/paper_files/paper/2025/hash/e6f1c64aa72e867b6dc54e87d1d196c8-Abstract-Datasets_and_Benchmarks_Track.html), [авторский PDF](https://www.cse.cuhk.edu.hk/~byu/papers/C300-NeurIPS2025-LithoSim.pdf).
- [Данные авторов](https://huggingface.co/datasets/grandiflorum/LithoSim), в карточке указана лицензия **AFL-3.0**. Полный репозиторий около 136 ГБ; скачивание целиком для этого аудита не требовалось.
- [Авторский код](https://github.com/dw-hongquan/LithoSim), лицензия Apache-2.0; на дату проверки репозиторий архивирован.
- [Использованный TRAIN-шард](https://huggingface.co/datasets/grandiflorum/LithoSim/resolve/main/lithosim/opc_metal/train_val/9987_to_9998.tar.gz): 6 009 313 байт, SHA-256 `249f469433d297eec065b17a40bd6ffbabab0406d881443e11e5713639d638b3`.

В статье задача — моделирование контура. Готовые классы «обрыв/замыкание/исправно» авторы не предоставляют. Для новой задачи нужны собственные проверенные правила разметки, а не переименование исходных меток.

## Что действительно установлено

В архиве 10 каталогов: `9987`, `9988`, `9989`, `999`, `9990`, `9993`, `9994`, `9996`, `9997`, `9998`. Каждый содержит исходную цель `layout.png`, скорректированную маску `mask.png`, описание источника `source_simple.src` и 33 результата `RI` для 11 значений `dose` и трёх `defocus`. Все PNG имеют размер 4096×4096 и **PIL mode1**. После чтения через NumPy это логические значения, поэтому порог `>127` здесь ошибочен.

**10 каталогов соответствуют лишь трём уникальным исходным топологиям.** Разные источники порождают разные OPC-маски одной цели. Поэтому разбиение только по номеру каталога недостаточно: нужно группировать все варианты одного `layout.png` по содержимому, включая возможные связи между metal и OPC-metal.

В этом шарде белая геометрия в опубликованных PNG **уменьшается** при увеличении `dose` в имени файла. Например, для `9988`, `defocus=0`, доля белых пикселей составляет 14,689% / 11,714% / 9,324% при `dose=-0.1 / 0 / +0.1`. Текст статьи описывает увеличение площади при положительном отклонении дозы. Физический знак параметра или смысл полярности пока не разрешены; порядок имён файлов нельзя без проверки переводить в утверждение об энергии экспонирования.

Вложенность белых областей приближённая. Из 30 фиксированных сочетаний источника и фокуса только одно даёт точное убывание множества по всем соседним дозам. Суммарно добавлены 38 798 белых пикселей, удалены 19 186 310. Нарушения составляют 0,2018% изменившихся пикселей. Малость пиксельной доли не гарантирует малости топологических ошибок.

## Проба классификационной разметки

Для проверки выполнимости, **не в качестве окончательной истинной разметки**, выбран набор точек глубоко внутри каждой связной компоненты исходного `layout.png`. Точки фиксированы по цели до просмотра `RI`. Прототип различает:

- обязательная точка исчезла либо точки одной исходной компоненты больше не связаны;
- точки разных исходных компонент оказались в одной печатаемой компоненте;
- оба события либо ни одно из них.

OPC-маска не используется как эталон связности: её корректирующие элементы не обязаны печататься. Связные компоненты цели не называются электрическими цепями, потому что netlist и связи за границей поля не известны.

На 330 изображениях получено: **310 без событий, 17 с разделением/исчезновением, 3 со слиянием, 0 с обоими событиями**. У этого конкретного набора точек нарушений ожидаемого порядка событий при изменении `dose` не найдено — ни на уровне всего изображения, ни отдельных компонент, ни пар. 21 компонентная кривая и 53 кривые пар содержат переход. Эти числа сильно зависимы, потому что исходных геометрий всего три.

Это подтверждает, что из доступных данных технически можно извлечь непостоянные классы и интервалы переходов. Это **не** подтверждение адекватности выбранных точек, полноты поиска отказов, достаточности классов или новой гипотезы. Одна точка не заменяет контактную область, 8-связность требует проверки чувствительности, а слияние геометрических фигур не доказывает электрическое короткое замыкание.

## Файлы и воспроизведение

- `audit_train_shard.py` — скачивание и полный аудит; архив читается через `extractfile`, без `extractall`, пути и типы записей проверяются.
- `AUDIT_RESULTS.json` — все 30 кривых, хеши исходных геометрий, точки и пробные классы.
- `six_panel_train.png` — цель, OPC-маска, три `RI` и разность для участка TRAIN. Участок выбран воспроизводимо по максимальному числу изменённых пикселей в фиксированной сетке, без классификатора.
- `LithoSim_NeurIPS2025.pdf` и `.txt` — первоисточник и текст с удалёнными служебными блоками latexit.
- `CHECKSUMS.json` — контрольные суммы файлов.

Из корня репозитория:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python gipoteza/hypothesis_search_20261024/lithosim_audit/audit_train_shard.py --fetch
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python gipoteza/hypothesis_search_20261024/lithosim_audit/audit_train_shard.py
```

Следующий необходимый шаг до постановки опыта: проверить соответствие точек реальному локальному отказу на более разнообразной **разработческой** части, направление параметра и достаточность независимых геометрий. Итоговый test для этого не нужен. Новая метрика топологии сама по себе не предлагается: ближайшая работа [Graph Loss, ESWA 2026](https://doi.org/10.1016/j.eswa.2026.132161) уже исследует недостаточность пиксельных метрик для таких дефектов.
