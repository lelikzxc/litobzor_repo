# SEM: проверка способа использования одинаковых классовых меток

Зафиксировано 28 октября 2026 до загрузки новых тестовых изображений и обучения.

## Вопрос

Улучшает ли непрерывная резисторная регуляризация классификацию бинарных
сегментаций по сравнению с обычным дополнительным классовым надзором,
получающим те же слабые примеры? Это новый ограниченный опыт одного ИС,
не проверка мирового приоритета или межчипового переноса.

## Данные

Авторский IC SEM M2, DOI 10.17617/3.HY5SYN, CC BY 4.0. TRAIN: кадры 0–5,
VAL: 6–7. TEST: восемь первых ещё не загружавшихся кадров по SHA256 строки
`SEM-FAIR-20261028/` + десятичный ID без ведущих нулей:
179,77,88,199,37,206,84,171. Исключены все 46 кадров из сохранённого
SOURCE_MEMBERS.json. Границы TEST не меняются при неудаче допуска данных.

Исключается полоса 512 нативных пикселей с каждой стороны. Это больше
заявленного автором перекрытия 10% кадра; остаточные пространственные
зависимости и один физический источник всё равно ограничивают вывод.
Изображение усредняется 4×4, маска уменьшается по большинству. Фрагмент
12×12, шаг 6; пустые/полные маски исключены. Точные D4-эквивалентные
бинарные мотивы дедуплицируются в порядке TRAIN → VAL → TEST и между
кадрами. Пересечение точных D4-эквивалентных полутоновых фрагментов также
исключается между частями. При повороте совместный класс меняется;
дедупликация группирует геометрию, но не объявляет её метку инвариантной.

Классы: два направления четырёхсвязной единичной резисторной модели;
три состояния на направление; совместный класс 3*cLR+cTB. Это вычисляемые
геометрические классы, а не независимо измеренные электрические отказы.

TRAIN: по 6 плотных и 128 слабых примеров каждого класса, упорядоченных
SHA256 канонического мотива: всего 54/1152. VAL: до 96/класс, не менее32.
TEST: все оставшиеся уникальные фрагменты выбранных кадров, не менее16
примеров каждого класса, каждый класс минимум в4кадрах. Если допуск не
пройден, обучение не запускать и сообщить результат подготовки.
Данные старых TRAIN/VAL уже использовались в проекте; это не новый
разработочный источник. Новые кадры не означают другой чип.

## Общий сегментатор и варианты надзора

CNN: Conv1→24(dilation1),24→24(dilation2),24→24(dilation4),24→1;
GELU после первых трёх слоёв, padding сохраняет12×12;10681параметр.
Нормировка5*(X−0.2). BCE-прогрев400шагов AdamW lr.003 wd.0001 batch16.
Каждый метод одного seed получает точную копию общих прогретых весов.

- replay: BCE только плотных масок;
- soft: прежняя c15: kappa4,a4,b40,min-ядро; подбирается только вес;
- head9: MLP3456→64→9 на пространственных признаках сегментатора, CE;
- head4: MLP3456→64→4, четыре порядковые BCE-цели двух направлений.

Головы видят те же 1152 слабых примера и метки. Их плотные маски не
передаются оптимизатору. Полные пространственные признаки сохранены;
глобальное усреднение, которое могло бы ослабить контроль, не используется.
Головы имеют дополнительные параметры: равенство ёмкости не заявляется.
Для усиления контроля перед совместным обучением голова отдельно
прогревается200шагов на слабых метках при замороженном backbone.
Это дополнительные head-only обновления; число обновлений сегментатора
у основных методов одинаково. Бюджет времени не объявляется идентичным.

## Выбор по VAL и итоговое обучение

Разработка: seed1701,1741;1000шагов дообучения для каждой конфигурации.
Вес каждого soft/head9/head4 выбирается из0.1,0.4,1.0 по среднему
VAL Macro-F1 класса из бинарной маски; при равенстве IoU, затем меньший
вес. Сильнейший тип головы выбирается по тому же VAL-правилу, не по TEST.
Проверяются все три веса для каждой семьи; у двух семейств головы
совокупный бюджет поиска больше, чем у soft, что усиливает контроль.

Итог: новые seed2801,2833,2887;2000шагов каждого выбранного метода
из своего общего400шагового BCE-прогрева;lr.001,wd.0001;батчи16плотных
+16слабых. Обе выбранные головы, soft и replay обучаются и сохраняются.
Все методы одного seed видят одинаковые индексы плотных и слабых батчей.
Последние веса; TEST не выбирает параметры, срок или лучший seed.

Для каждой головы дополнительно сообщается её прямой класс. Основной
показатель всех вариантов относится к классу из бинарной сегментации;
прямой выход головы — отдельная практическая оценка без подмены маршрута.

## Метрики и заранее заданное решение

Основная метрика: Macro-F19классов по объединённым фрагментам каждого
seed, затем среднее трёх seed. IoU — среднее по фрагментам и seed.
4000парных crossed-bootstrap-повторов: независимо пересэмплировать
тестовые кадры и seed, суммировать confusion по кадрам до F1.
Одинаковые индексы для методов, bootstrapseed281028.

Критерий PASS_PILOT: soft превосходит replay И выбранную по VAL
сильнейшую голову по Macro-F1 масочного маршрута минимум на1п.п.;
нижняя граница каждого парного95%интервала>0; IoU не хуже каждого
контроля более2п.п. Все требования обязательны. Совпадающие результаты,
провал интервала или отрицательный эффект не объявляются подтверждением.
Сравнения с обоими типами головы и прямыми головами публикуются целиком.

Новые тестовые кадры предназначены только для этой проверки; последующее
использование делает их разработочными. Восемь кадров одного чипа и
три seed дают ограниченный пилот, не промышленную или внешнюю репликацию.

## Исполнение и сохранность

Все новые файлы внутри sem_confirmation_20261028/. Исторические данные,
протоколы и текущий gipoteza.md не изменяются. Сохраняются исходные PNG,
SVG, SHA/CRC, split/канонические ключи, код, протокол, выбранные параметры,
веса, прогнозы и прогресс. MPS требуется явно, CPU-fallback не допускается.
Резисторный решатель и bootstrap работают на CPU. Прогресс каждые100шагов.
При ошибке исправления фиксируются; TEST не используется для отладки.
