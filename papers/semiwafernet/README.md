# SemiWaferNet reproduction

Reference: **SemiWaferNet: Efficient Semi-Supervised Hybrid CNN-Transformer Models for Wafer Defect Classification and Segmentation**, Electronics 2026, 15, 1437, https://doi.org/10.3390/electronics15071437 (`semiwafernet.pdf`).

Two separate models: HybridCNN-ViT for classification (32x32, nine classes) and ConvoFormer-UNet for binary segmentation (64x64). Full training is required to assess the paper's recognition quality. CPU training is supported, but the repeated MC-dropout passes make the full SSL experiment much slower than a short supervised run. Unit tests and short runs do not establish paper-level recognition quality.

## Run on GPU

Install the repository requirements, including `imbalanced-learn`, and a CUDA-compatible PyTorch/torchvision pair. The paper uses PyTorch 2.5.1. Work from the repository root.

```bash
# Classification: official training/test partition, 150k unlabeled, 50 total epochs.
python papers/semiwafernet/train.py --config papers/semiwafernet/configs/config.yaml --device cuda
python papers/semiwafernet/evaluate.py --checkpoint checkpoints/semiwafernet_reproduction/best.pt --device cuda

# Segmentation: generate masks from original categorical defective die == 2.
python papers/semiwafernet/prepare_segmentation.py
python papers/semiwafernet/train.py --config papers/semiwafernet/configs/config_segmentation.yaml --device cuda
python papers/semiwafernet/evaluate.py --checkpoint checkpoints/semiwafernet_seg_reproduction/best.pt --device cuda
```

Classification requires `datasets/wm811k/labels.csv` with `filename`, `failureType` and `trianTestLabel`, plus original PNG maps in `images/`. An empty failureType is unlabeled; `none` is a real class. The entry point fails if an explicitly requested official split or SSL pool is missing, rather than silently changing the experiment. To run a supervised ablation, use `--no-ssl` and a separate checkpoint directory.

The segmentation preparation writes a separate `datasets/semiwafernet_seg` and refuses to mix files into an existing nonempty output. It excludes None/Random and generates masks **before resizing**, using original die state 2. It does not change datasets used by other models. The old common generator expected value 254 and did not recognise `failureType`, so it was unsuitable for the current raw 0/1/2 export. Do not reuse masks generated by that script without inspection.

`protocol.json` beside checkpoints records the exact evaluation sample indices and configuration. Standalone evaluation loads the saved configuration by default. Keep it with checkpoints when moving to another machine. `last.pt` remains the resumable final epoch; `best.pt` is selected by validation macro-F1 for classification and foreground IoU for segmentation.

SSL restarts are supported at stage boundaries:

```bash
python papers/semiwafernet/train.py --config papers/semiwafernet/configs/config.yaml --resume checkpoints/semiwafernet_reproduction/ssl_stage1.pt --ssl-start-stage 2 --device cuda
```

Use `ssl_stage2.pt --ssl-start-stage 3` analogously. Mid-stage `last.pt`/`best.pt` is not accepted as an exact SSL restart: pseudo-label/RNG state is not stored for every batch. Boundary restarts regenerate pseudo-labels and are not bit-for-bit continuations. For a separate restart experiment, choose a fresh checkpoint directory. Previous checkpoints keep their original format and are not overwritten by the new default paths.

## Failure analysis and corrections

- **Wrong resampling:** previous “SMOTE” default was RandomOverSampler. Its optional SMOTE interpolated categorical numbers and rounded them back, deleting interpolation. The main recipe now applies actual SMOTE in flattened one-hot input space and retains soft interpolated features. `data.oversample_method: random` remains an explicit ablation, storing duplicate indices instead of duplicate images.
- **Checkpoint error:** SSL bypassed `engine.fit`, so it never selected/saved a current best model. Final evaluation could load a stale `best.pt` from an earlier run. Each SSL epoch now validates and checkpoints; Stage 1/2/3 transfer their best validated student to the next teacher. Restoring best weights also restores matching Adam moments.
- **Unnecessary memory growth:** pseudo generation retained all 150k image tensors, and union construction repeatedly copied/stacked labeled and pseudo data. The deterministic unlabeled loader now stores candidate statistics and accepted source indices; the union loader accesses source datasets lazily and applies fresh augmentation.
- **Selection deviations:** the “disabled” None cap still removed most examples when all accepted labels were None. `null` now truly disables capping. Singleton confidence standard deviation is zero; population statistics and Eq. 10 thresholds are tested. The published raw-entropy/MI thresholds remain fixed, with no prior-logit adjustment.
- **Broken binary segmentation path:** the config provided three channels for one-channel data; segmentation optimiser settings were not propagated; multiclass Dice/Focal cannot train a single-channel defect head; the generic trainer could not detach auxiliary-output dictionaries; classification metrics were unsuitable. Corrected mode config, binary Dice/Focal, tensor-output adapter with auxiliary gradients, foreground metrics and IoU checkpoint selection cover this path.
- **CLI/protocol issues:** `--lr` now changes the optimiser actually used. `--epochs 1` means one warm-up epoch instead of three epochs. Global RNGs are seeded. Training class counts exclude validation samples. The shared trainer honours the configured checkpoint metric instead of always using accuracy.

## Publication ambiguities

The paper does not specify the classification channel encoding/interpolation, None downsampling ratio, pseudo-evaluation holdout fraction, per-stage epoch allocation, SMOTE feature representation, whether CE class counts are before or after balancing, exact augmentation magnitudes, or detailed segmentation widths/split. Explicit choices remain: categorical one-hot channels with nearest-neighbor resizing, None ratio 0.30, pseudo-evaluation 5%, stages 17/17/16, one-hot SMOTE, post-balancing CE counts, category-preserving flips/90-degree rotations, segmentation 80/10/10 split and width 66/embed 160. These choices are not claims of exact author-code parity. Balanced CE counts make the published inverse-square-root weights uniform; `ce_count_source: natural` or `hybrid` are available as separate ablations.

For unequal class weights the implementation uses PyTorch's standard weighted-mean CE, dividing by the sum of target weights in the batch. The printed Eq. 14 divides by batch size with unnormalised inverse-square-root weights. Relative class weights agree, but the loss/gradient scale is a further implementation choice; literal numerical equality to that equation is not claimed.

The paper's per-class “Avg accuracy” corresponds to macro-recall, while overall accuracy and macro-F1 are distinct metrics. Keep these separate when comparing tables. The segmentation mask is deterministically encoded in the input die map, so very high reported overlap concerns reconstruction of die states rather than independently annotated physical defects.

A fast CPU smoke is `--ssl-fast --data-fraction 0.0001 --device cpu` with a separate checkpoint directory. It checks all stages; an untrained teacher accepting zero pseudo-labels in this smoke is expected. It is not a quality benchmark. Use `python -m pytest tests/test_paper_reproduction.py -q` for focused regression checks.

## CPU learning diagnostics

The local WM-811K export was audited on 2026-10-06: 811,457 CSV records, 811,457 unique PNGs, no missing/extra images; 172,950 labeled (54,355 official Training / 118,595 Test) and 638,507 unlabeled. This is the complete public dataset, not just its labeled subset.

These runs retain the full 788,169-parameter classifier and the published learning rate, batch size, dropout and weight decay. They use a stratified 10% subset and 10 supervised epochs, with 2,580 real training maps becoming 8,928 after SMOTE, 545 validation maps and 11,860 test maps. They test learning behaviour, not the full three-stage paper protocol. The weighted variant changes only the CE count source and checkpoint directory. Choose checkpoints using validation, never test results.

```bash
OMP_NUM_THREADS=4 python papers/semiwafernet/train.py --config papers/semiwafernet/configs/config_cpu_diagnostic.yaml --data-fraction 0.1 --device cpu --no-ssl
OMP_NUM_THREADS=4 python papers/semiwafernet/train.py --config papers/semiwafernet/configs/config_cpu_weighted.yaml --data-fraction 0.1 --device cpu --no-ssl
python papers/semiwafernet/evaluate.py --checkpoint checkpoints/semiwafernet_cpu_diagnostic/best.pt --device cpu
```

Diagnostic checkpoints, logs and generated reports live in separate `checkpoints/semiwafernet_cpu_*` directories. They do not overwrite reproduction or previous experiment checkpoints.

The completed 10-epoch unweighted diagnostic reduced training loss from 1.7387 to 0.5286. Its best checkpoint (epoch 8, validation macro-F1 0.6770) scored **0.576981 test accuracy, 0.354619 macro-F1 and 0.462172 macro-recall** on the saved 11,860-map test subset. These results do not reproduce the paper; the validation/test gap cannot be dismissed by citing unit-test success. Detailed per-class metrics are saved in `checkpoints/semiwafernet_cpu_diagnostic/results.json`. The weighted comparison was interrupted before completing its 10 epochs, so no completed head-to-head comparison or default change is inferred from it.

Measured CPU throughput with four threads was about 298 training images/s (batch 256), 874 deterministic inference images/s and 599 MC-dropout inference images/s. Two pseudo-label refreshes alone process 6 million inference examples and take roughly 2.8 hours at the measured MC rate; the 50 training epochs and accepted pseudo-labels add further hours. GPU training is the practical next quality experiment, after the CUDA-specific regression checks pass on that device.
